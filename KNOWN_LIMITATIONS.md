# Known limitations

1. **Live quality is unverified.** Real provider adapters are implemented and contract-tested, but no keys or local LLM were available. The default is explicitly a scripted demo. Account model/voice availability can differ; all identifiers are configurable.
2. **Browser QA was blocked.** The browser host was unavailable; npm registry access was denied. Supplied Playwright tests have not passed yet. Layout, browser permission dialogs and actual device speech need execution in a usable browser environment.
3. **Voice transport is a cascade.** Hands-free captures bounded utterances, transcribes, streams model text, then synthesizes buffered sentence-sized audio. It is not LiveKit/WebRTC native audio streaming and does not synthesize while model tokens are still arriving. Expect network/model/TTS delay; no latency guarantee is made.
4. **VAD is energy-based.** It requests browser echo cancellation and uses noise adaptation/pre-roll, but cannot distinguish other speakers, acknowledgements and intended interruptions reliably in every room. Headphones and the manual recording mode are the fallback. No speaker identification is implemented.
5. **Delivered-speech tracking is approximate.** Completed segments are acknowledged. The interrupted segment’s exact heard words are unknown, and normalized speech can differ in length from displayed text. Later context marks interrupted audio rather than assuming everything was heard. Aborted partial text generation is discarded from persistent history.
6. **Filipino voice authenticity requires listening.** Listed language support is not proof of accent or fluent Taglish. Azure Blessica uses supported prosody, without unsupported expressive-style claims. Device speech availability varies. Device voices do not expose PCM, so no fake mouth sync is generated. Natural nonverbal laughter is not guaranteed or separately synthesized.
7. **OpenAI legacy TTS has an expiry.** Current official documentation says the implemented compatibility endpoint models retire January 6, 2027. Prefer Azure/device synthesis until a proper Realtime migration is implemented. Do not plug a Realtime model into the speech endpoint.
8. **Memory logic is conservative.** Literal-excerpt grounding and sensitivity filters are heuristics, not semantic proof. Contradiction detection is limited to recognizable prefixes. Every suggested note still needs user approval. Memory retrieval is lexical/recency-based; confidence defaults to 1 for confirmed notes. Expiry/supersession metadata is available but no automatic expiry scheduler or complete semantic contradiction engine exists.
9. **Deleting a note does not delete original chats or backups.** Summaries are invalidated and matching sources excluded, but recent chat history can still contain the original text. Delete that conversation too to remove it from active chat context. Provider retention, exported files and external backups are independent. Usage-only counters remain after erasure to enforce ceilings.
10. **Knowledge retrieval is small and bounded.** TXT/MD only, no PDF/Office parsing or web search. Default vectors are lexical hashes, not learned semantic embeddings. Optional OpenAI embeddings apply to document retrieval. Re-ingest after model changes; no automatic index migration exists.
11. **This is not a hosted multi-user service.** Loopback and same-origin protections are implemented, but the process token is not account authentication. Some records have owner scope while settings/usage assume one owner. Never expose it publicly without an authorization and isolation redesign. The database is not encrypted.
12. **Cost/timing reports have limits.** Reservations and provider-reported tokens are tracked; no price assumptions are hardcoded, so dollar estimates are unavailable. Counts are conservative and do not guarantee billing limits. Client playback-start/stop-call metrics do not measure acoustic sound at the ear. There is no production telemetry dashboard.
13. **Avatar runtime setup remains external.** The user-supplied Niziiro Mao PRO model is selected and integrated, but Cubism Core and the pinned Pixi/display runtime are absent; npm access was denied. Follow `MODEL_SETUP.md`. The panel truthfully shows a setup message until those files are installed. Actual Live2D rendering is unverified. VTube Studio requires explicit local API permission and correct parameter/hotkey mappings; it is mock-tested only. BroadcastChannel overlay needs a shared origin/storage partition; a separate OBS browser engine may not receive it.
14. **Preferred larger stack was not adopted.** The dependency-free JavaScript/Node/SQLite app preserves a runnable Windows implementation under installation restrictions. React/TypeScript, FastAPI, PostgreSQL/pgvector and LiveKit are not present. `contracts.d.ts` describes injectable boundaries; it is not a claim of full TypeScript compilation.

Highest-value next step: configure a provider, run the supplied browser tests, and complete the voice audition/real-device interruption matrix. Use those measurements to choose whether native streaming STT/TTS or a LiveKit/WebRTC session warrants the added infrastructure. Fine-tuning remains a future option requiring consented curated data and before/after evaluation; there is no automatic retraining.
