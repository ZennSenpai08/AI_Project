# Mao avatar setup

Hiraya now selects the user-supplied **Niziiro Mao PRO** visual model in `mao_en/runtime/mao_pro.model3.json` by default. This changes the visual avatar; Hiraya's character configuration, conversation provider, and synthetic voice remain separate. The original model and editor files are preserved.

## Install the browser runtime

The model folder contains artwork, compiled model data, physics, motions, and expressions, but no JavaScript renderer. The core app still starts without these libraries and shows an explicit avatar setup message. Installation could not be completed here because npm access returned `EACCES`.

From the project directory in a normal environment with npm access:

```powershell
npm --prefix avatar-runtime install
```

Download **Cubism SDK for Web** from the [official Live2D SDK page](https://www.live2d.com/en/sdk/download/web/), review its terms, and extract it locally. Use its `Core/live2dcubismcore.min.js` (Cubism 5-compatible Core). Then run:

```powershell
npm run setup:avatar -- "C:\path\to\CubismSdkForWeb\Core\live2dcubismcore.min.js"
npm start
```

Replace the example path with the extracted Core file. If the server is already running, stop it first. Open or reload **http://127.0.0.1:3210**. The setup script validates every input before copying runtime files into `public/vendor/live2d/`. That generated directory is ignored by Git. Keep the SDK license documents with your local distribution.

The optional package pins `pixi.js@7.4.3`, `@pixi/unsafe-eval@7.4.3`, and `pixi-live2d-display-lipsyncpatch@0.5.0-ls-8`. Its `cubism4.min.js` build name also covers Cubism 5 through the supplied Core. The official Pixi CSP patch avoids requiring JavaScript `unsafe-eval`; CSP allows WebAssembly compilation only. Scripts are served locally, with no runtime CDN dependency. The optional package lockfile must be generated by the successful install; none was fabricated while registry access was blocked.

## Configuration and behavior

`AVATAR_PROVIDER=live2d` is the default, so no `.env` change is required. To intentionally use the earlier original SVG instead, set `AVATAR_PROVIDER=svg` and restart.

- The manifest's idle motion, physics, and pose are loaded by the renderer.
- Warm/calm/curious use `exp_01`, playful uses `exp_02`, concerned uses `exp_05`, and excited uses `exp_04`. Expressions change per emotion, not per token. Special magic motions are not triggered automatically.
- Mouth movement uses the supplied model's **`ParamA`** LipSync group and actual cloud-audio playback amplitude. It closes on stop/interruption. Device speech exposes no PCM, so it does not produce artificial mouth motion.
- Hiding the avatar or browser tab pauses its rendering. Leaving the page disposes the canvas, observers, and renderer resources.
- `/avatar.html` uses the same model for a transparent overlay in a shared browser origin/storage partition. A separate OBS browser engine needs an additional bridge for live events.
- `/api/avatar` reports model/runtime availability. Runtime presence does not prove WebGL compatibility. Loading failures appear in the character panel without breaking chat.

If the setup message remains, check that all four files named by `npm run setup:avatar` exist. For a rendering error, check the browser console, WebGL support, the official Core version, and the extracted model contents. Do not rename `ParamA` to `ParamMouthOpenY`.
