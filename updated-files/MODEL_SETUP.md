# Actual model setup and capabilities

Source: supplied ../mao_en/runtime/mao_pro.model3.json and original ../mao_en/ReadMe.txt. Live2D Niziiro Mao PRO, not a VRM skeleton or original Zyrah illustration. Seven authored motions, eight expressions, ParamA lip sync, blush, head/body angles, gaze, blink/smile and alternate A/B arm poses. Runtime parameter inventory from executed browser inspection is artifacts/browser/model-parameters.json.

npm ci --prefix avatar-runtime; npm run download:core; npm run setup:avatar. Core source and checksum are in scripts/download-core.js. Pixi 7.4.3 and display 0.5.0-ls-8 were exercised with actual assets on Windows. CSP uses wasm-unsafe-eval and Pixi's official CSP patch; JavaScript unsafe-eval remains disabled.

Settings → Character performance preview runs wave, amusement, thinking, embarrassment, tease, concern and celebration. Cooldown is 4.5 seconds. Arm B is used for the greeting; parameter bounds are read from the actual runtime. Blush is supported (ParamCheek). No heart eyes/tears coverage is promised. Default authored idle motions are disabled to prevent their mouth/arm tracks fighting controlled layers. Blink remains runtime-owned, vowels are playback-owned, and pose values return through smoothing.

Performance intent is bounded; providers cannot send arbitrary model transforms. Speech reactions start at the first segment's actual playback callback. Without speech, text reactions begin after the response. Thinking starts while waiting. Cancellation clears pending/active cues. Facial emotion follows a validated enum; gesture timing/gaze come from deterministic controller values. Current hand shapes produce a raised wrist gesture rather than a verified open-palm wave. Audio laughter requires a supported voice engine; preview never fakes it.
